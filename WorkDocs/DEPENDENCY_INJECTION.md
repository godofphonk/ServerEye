# Dependency Injection Implementation with Google Wire

## Overview

This document describes the implementation of dependency injection (DI) using Google Wire in the ServerEye agent. This refactoring improves testability, maintainability, and follows enterprise-level architecture principles.

## Architecture Changes

### Before (Manual Dependency Initialization)

```go
type Agent struct {
    config            *config.AgentConfig
    logger            *logrus.Logger
    wsPublisher       *metrics.WebSocketPublisher        // Concrete type
    wsCommandConsumer *commands.WebSocketCommandConsumer // Concrete type
    cpuMetrics        *metrics.CPUMetrics                 // Concrete type
    systemMonitor     *metrics.SystemMonitor              // Concrete type
    dockerClient      *docker.Client                      // Concrete type
    // ...
}

func New(cfg *config.AgentConfig, logger *logrus.Logger) (*Agent, error) {
    // Manual initialization with tight coupling
    wsPublisher := initializeWebSocketPublisher(cfg, logger)
    wsCommandConsumer := initializeWebSocketCommandConsumer(cfg, tempAgent, logger)
    // ...
}
```

### After (Interface-based with DI)

```go
type Agent struct {
    config            *config.AgentConfig
    logger            interfaces.Logger
    wsPublisher       interfaces.MetricsPublisher    // Interface
    wsCommandConsumer interfaces.CommandConsumer     // Interface
    cpuMetrics        interfaces.MetricsCollector     // Interface
    systemMonitor     interfaces.SystemMonitor        // Interface
    dockerClient      interfaces.DockerManager        // Interface
    // ...
}

func InitializeAgent(ctx context.Context, configPath string) (*Agent, error) {
    // Dependencies injected by Wire
    wire.Build(
        ProviderSet,
        wire.Bind(new(interfaces.CommandHandler), new(*Agent)),
    )
}
```

## Implementation Details

### 1. Interface Definitions

Created comprehensive interfaces in `internal/interfaces/interfaces.go`:

- **MetricsCollector**: CPU temperature collection
- **SystemMonitor**: System resource monitoring (memory, disk, network, processes)
- **DockerManager**: Docker container management
- **MetricsPublisher**: WebSocket metrics publishing
- **CommandConsumer**: WebSocket command consumption
- **CommandHandler**: Command processing
- **Logger**: Structured logging interface
- **Config**: Configuration management

### 2. Wire Configuration

**File**: `internal/agent/wire.go`

```go
//go:build wireinject
// +build wireinject

package agent

import (
    "github.com/google/wire"
    // ... other imports
)

// ProviderSet is a collection of providers for the agent package
var ProviderSet = wire.NewSet(
    provideLogger,
    provideConfig,
    provideMetricsCollector,
    provideSystemMonitor,
    provideDockerManager,
    provideMetricsPublisher,
    provideCommandConsumer,
    provideAgent,
)

// InitializeAgent creates a new agent with dependency injection
func InitializeAgent(ctx context.Context, configPath string) (*Agent, error) {
    wire.Build(
        ProviderSet,
        wire.Bind(new(interfaces.CommandHandler), new(*Agent)),
    )
    return nil, nil // This will be replaced by Wire
}
```

### 3. Provider Functions

Each dependency has a dedicated provider function:

```go
// provideLogger creates a new logger instance
func provideLogger() interfaces.Logger {
    logger := logrus.New()
    logger.SetFormatter(&logrus.TextFormatter{
        FullTimestamp: true,
        ForceColors:   true,
    })
    return logger
}

// provideMetricsCollector creates a new metrics collector
func provideMetricsCollector() interfaces.MetricsCollector {
    return metrics.NewCPUMetrics()
}

// provideSystemMonitor creates a new system monitor
func provideSystemMonitor(logger interfaces.Logger) interfaces.SystemMonitor {
    logrusLogger := logger.(*logrus.Logger)
    return metrics.NewSystemMonitor(logrusLogger)
}
```

### 4. Generated Code

**File**: `internal/agent/wire_gen.go` (auto-generated)

```go

package agent

import (
    "context"
    // ... imports
)

// InitializeAgent creates a new agent with dependency injection
func InitializeAgent(ctx context.Context, configPath string) (*Agent, error) {
    config, err := provideConfig(configPath)
    if err != nil {
        return nil, err
    }
    logger := provideLogger()
    metricsCollector := provideMetricsCollector()
    systemMonitor := provideSystemMonitor(logger)
    dockerManager := provideDockerManager(logger)
    metricsPublisher, err := provideMetricsPublisher(config, logger)
    if err != nil {
        return nil, err
    }
    commandConsumer, err := provideCommandConsumer(config, &Agent{}, logger)
    if err != nil {
        return nil, err
    }
    agent, err := provideAgent(ctx, config, logger, metricsCollector, systemMonitor, dockerManager, metricsPublisher, commandConsumer)
    if err != nil {
        return nil, err
    }
    return agent, nil
}
```

## Benefits Achieved

### 1. **Testability**

**Before**: Hard to test with concrete dependencies
```go
// Difficult to mock concrete types
func TestAgent(t *testing.T) {
    agent := &Agent{
        wsPublisher: &metrics.WebSocketPublisher{}, // Can't easily mock
    }
}
```

**After**: Easy mocking with interfaces
```go
func TestAgentWithDI(t *testing.T) {
    mockMetricsPublisher := &MockMetricsPublisher{}
    mockMetricsPublisher.On("Start", mock.Anything).Return(nil)
    
    agent := &Agent{
        wsPublisher: mockMetricsPublisher, // Easy to mock
    }
}
```

### 2. **Flexibility**

- Runtime configuration of dependencies
- Easy swapping of implementations
- Support for different environments (dev/staging/prod)

### 3. **Maintainability**

- Clear dependency graph
- Separation of concerns
- Interface-driven development

### 4. **Enterprise-Level Architecture**

- SOLID principles compliance
- Dependency inversion
- Single responsibility

## Migration Guide

### Step 1: Interface Definition
1. Identify all concrete dependencies
2. Create interfaces for each dependency
3. Update struct fields to use interfaces

### Step 2: Wire Setup
1. Install Wire: `go get github.com/google/wire/cmd/wire`
2. Create `wire.go` with provider functions
3. Generate code: `go generate ./internal/agent`

### Step 3: Testing
1. Create mock implementations
2. Update tests to use mocks
3. Verify behavior with dependency injection

### Step 4: Integration
1. Update main.go to use `InitializeAgent`
2. Update configuration if needed
3. Test in different environments

## Best Practices

### 1. Interface Design
- Keep interfaces small and focused
- Follow the interface segregation principle
- Use composition over inheritance

### 2. Provider Functions
- Keep providers simple and single-purpose
- Handle errors appropriately
- Use descriptive names

### 3. Testing
- Mock external dependencies
- Test both success and failure scenarios
- Use table-driven tests for multiple cases

### 4. Code Generation
- Commit generated code to version control
- Regenerate when interfaces change
- Use build tags for conditional compilation
